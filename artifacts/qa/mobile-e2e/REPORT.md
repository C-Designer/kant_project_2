# 모바일 전체 흐름 검증 — 2026-10-11

모드: exploratory QA + UI polish. 대상: localhost:3100 Next 프로덕션 v0.3, localhost:8100 API, 익명·가상 입력/고정 예시. Surface: 호스트 Codex IAB. 기존 설치만 사용. 이번에 만든 예시는 삭제로 정리한다. 키는 파일/캡처에 기록하지 않는다.

## 실행 전 기대
1. 390px 입력: 빈 제출은 필수 입력에서 막힘. 가상 두 사람 입력, 생시 모름 처리, 동의 후 현재 분석 준비 중 안내. 입력값 유지, 예시 결과로 쉽게 이동 가능.
2. 예시: 고정 예시 표시, 네 축과 해설, 320px에서도 넘침 없음. 동의 전 공유 차단, 동의 후 생성.
3. 공유: 복사 상태와 별도 탭 조회·새로고침으로 저장 확인. 삭제 정보는 공유 링크와 분리.
4. 관리: 잘못된 삭제 정보 안내, 확인창 취소·초점 복귀, 이번 예시 최종 삭제 후 성공 표시. 공유 탭 새로고침으로 결과 접근 차단.
5. 수정 발견 시 동일 흐름 재확인, 빌드 및 적절한 기존 검증 실행.

## 개선과 근거

- P2 입력 하단 안내에는 예시 진입 동작이 없어서 긴 폼 위로 돌아가야 함(직접 관찰). `input-before.png`와 `input-after.png`. 준비 중 안내 아래에 입력과 별개인 고정 예시 버튼을 추가했고 다시 실행하여 진입 확인.
- P3 복사 성공이 모두 '복사했어요.'로 동일(직접 관찰). 공유 링크/삭제용 정보로 완료 문구를 구분했고 실제 버튼 두 개·클립보드 일치 확인.
- P3 공유 결과 만료 표시는 브라우저 시간대에 의존(코드 검토). Asia/Seoul로 고정하고 한국 시간 문구 추가. 실제 공유 조회 화면 확인. 다른 OS 시간대로 변경하는 실험은 하지 않음.
- `npm --prefix frontend run build` 통과(TypeScript 포함). 백엔드는 변경하지 않음.

## 증거와 한계

Surface: host-managed Codex IAB, Next production, CSS390/320px. 실제 모바일 기기·Safari·소프트 키보드 테스트는 아님. 최종 스크린샷 `result320.png`, `delete-success320.png`, `deleted320.png`. 첫 별도 탭 캡처 `deleted390.png`는 도구의 새 탭 기본 viewport1280으로 관찰되어 모바일 근거로 쓰지 않음. 최종320px 재실행이 모바일 조회·삭제 근거다.

수집한 browser warning/error 0건. 네트워크 trace는 제공된 surface에서 수집하지 않았으므로 HTTP 상태·외부 요청 부재를 브라우저 네트워크 증거로 단정하지 않음. 준비 중 분석·삭제 후 조회는 의도된 실패 UI로 확인. 스크린리더·시간 경과7일·오프라인·실제 모델 분석은 미실행.

접촉 대상은 로컬3100/8100, 계정 없음. 가상 날짜/MBTI만 입력. 이번에 만든 예시2건 모두 제품 삭제 흐름으로 정리. 공유 키는 파일·캡처에서 제외. 기존 사용자의 데이터나 이전 실행 데이터는 건드리지 않음. 캡처는 로컬 artifacts/qa/mobile-e2e에 보관(Git 제외), 검토 후 이 디렉터리만 삭제 가능.
