## 1. 문제와 제품 방향

단순한 궁합 점수보다 “두 사람이 어떤 방식으로 관계를 맺는지”를 쉽게 읽고 나눌 수 있는 결과를 제공한다. 점수·등급으로 관계를 평가하지 않고, 네 축의 스타일과 잘 맞는 점·맞춰 갈 점을 설명한다.

이는 사용자 요청과 제안서에서 정한 제품 가설이다. 실제 이용자 인터뷰, 사용성 테스트, 수요·전환율 자료는 아직 없다. 사주·MBTI 기반 유형은 팀이 정의한 오락용 분류 체계이며 관계의 미래를 입증하거나 예측하는 검사가 아니다.

### 사용자와 역할

| 역할 | 원하는 일 | 범위 |
| --- | --- | --- |
| 분석 요청자 | 두 사람의 정보를 입력하고 결과 읽기 | 로그인 없이 이용 |
| 공유 링크 수신자 | 전달받은 결과 읽기 | 원본 입력 열람·수정·삭제 불가 |
| 삭제 권한 보유자 | 저장한 결과와 공유 링크 폐기 | 최초 저장 시 받은 삭제키 필요 |
| 프로젝트 팀 | 가상 데이터 검수, 모델 비교, 시연 운영 | 사용자용 관리 화면 없이 개발 도구 사용 |

프로토 페르소나: 관계를 가볍게 이야기할 소재를 찾는 한국어 사용자. 연령·성별별 선호는 조사하지 않았으며 이에 따른 UI 차별화는 하지 않는다.

## 2. 확정 범위와 제외 범위

### 포함

- 한 사람이 두 사람의 성별·양력 생년월일·출생시각·MBTI를 입력한다.
- 생시 모름을 허용하고 해당 인물의 시주를 제외한다.
- 만세력 결과와 MBTI를 텍스트로 만든 뒤 모델이 **16유형 중 하나**를 분류한다.
- 네 축의 한글 라벨, 한 줄 요약, 강점, 맞춰 갈 점, 대화 제안을 보여준다.
- 사용자가 원할 때 결과만 서버에 저장하고 읽기 전용 공유 링크를 만든다.
- 링크 재열람, 7일 만료, 삭제키를 통한 삭제를 제공한다.
- 모바일·데스크톱 반응형, 입력 오류·생성 실패·링크 만료·삭제 상태를 구현한다.
- TF-IDF+LR 대 사전학습 인코더 분류 모델 비교와 OpenAI 해설 실험을 준비한다. API 라벨링 이후 실제 학습·평가하며 로컬 생성 모델 비교는 제외한다.

### 제외

회원가입, 로그인, 결제, 광고, 관리자 웹화면, 결과 목록·검색, 이메일·메신저 자동 발송, 이미지 다운로드, 푸시, 실시간 공동 입력, 출생지·경도 보정·음력 입력, 별도 성향 문답, 관계 단계·닉네임·고민 문장 수집, 속궁합·외도 가능성 판정, 궁합 점수·확률·등급, 자동 재분석, 공개 검색 노출은 범위 밖이다.

원문 Plan B는 현재 범위가 아니다. 분류 과제 요건 변경이 확인될 때 별도 개정한다.

## 3. 관계유형 표현

| 축 | 두 극 | 사용자에게 설명하는 차이 |
| --- | --- | --- |
| 연애 케미 | 닮은꼴 / 보완형 | 비슷해서 편한지, 달라서 채우는지 |
| 연애 온도 | 열정형 / 안정형 | 강렬하게 표현하는지, 잔잔하게 이어가는지 |
| 관계 거리 | 밀착형 / 독립형 | 함께하는 시간과 각자의 공간 중 어디에 무게를 두는지 |
| 갈등 해결 | 바로 풀기 / 시간 두기 | 즉시 이야기하는지, 정리한 뒤 이야기하는지 |

현행 노션 명칭을 유지한다. 이전 대화의 대체 명칭은 채택하지 않는다. 화면에는 네 개 라벨을 풀어 쓰고 내부 유형 ID·4글자 코드는 보여주지 않는다. 16개 조합은 [유형 사전](./DATA_SCHEMA.md#4-관계유형-사전)에서 관리한다. UI에서 조합을 표시하는 것과 모델이 각 축을 독립적으로 분류하는 것은 구분한다.

## 4. 핵심 흐름

1. 소개: “우리 둘은 어떤 커플일까요?”와 참고·오락용 안내, `궁합 알아보기`.
2. 입력: `첫 번째 사람`, `두 번째 사람` 순서로 입력. 양력·한국 표준시 기준을 미리 알린다.
3. 확인: 두 사람의 정보를 분석 목적으로 입력해도 되는지 확인 체크. 기본값은 미선택이다.
4. 분석: 서버 처리 중 입력·중복 제출을 잠그고 `두 사람의 관계 스타일을 살펴보고 있어요` 표시. 가짜 진행률을 쓰지 않는다.
5. 결과: 네 라벨 → 요약 → 강점 → 맞춰 갈 점 → 대화 제안 → 참고 안내. 생시를 모르면 제한을 결과에 표시한다.
6. 선택 공유: `공유 링크 만들기`를 누르면 저장 범위·7일 보관·링크 보유자 열람·삭제키 안내를 먼저 보여준다. 확인 후에만 저장한다.
7. 저장 완료: 읽기 링크 복사, 만료일, 삭제키 별도 복사. 복사는 사용자 동작으로만 실행하며 외부 서비스에 자동 전송하지 않는다.
8. 재열람·삭제: 링크는 읽기 전용이다. 삭제키 보유자는 `/manage`에서 결과를 폐기한다. 삭제 후 복원은 제공하지 않는다.

저장 전 결과는 현재 탭의 메모리만 사용한다. 새로고침·탭 종료 시 사라진다. 저장 가능 시간은 분석 완료 후 10분이며 초과하면 재분석을 안내한다. 이미 저장한 링크는 7일 동안 다시 열 수 있다. 삭제키를 잃으면 로그인 복구가 없으므로 수동 삭제가 불가능하며 자동 만료를 기다린다.

## 7. 성공 기준과 과제 증거

현재 기준선은 전부 미측정이다. 아래 수치는 성과 주장이 아니라 이번 설계의 목표다.

| 목표 | 목표·선정 규칙 | 측정 방식 / 시점 | 제한 |
| --- | --- | --- | --- |
| 주요 흐름 완료 | 핵심 시나리오 전부 통과 | 테크스펙 인수 테스트, 시연 후보마다 | 실제 사용자 전환율로 해석하지 않음 |
| 개인정보 최소화 | 원본 입력 저장·외부 전송 위반 0건 | DB·로그·네트워크 검사, AI·공유 연결 시 | 실패 1건이라도 시연 입력 제한 |
| 분류 모델 비교 | 동일 분할에서 validation Macro-F1 우선, Accuracy·지연 순으로 동률 해소 | 600쌍 또는 명시한 300쌍, test 최종 1회 | 팀 라벨 재현 성능이지 관계 예측 정확도가 아님 |
| 해설 비교 | 개발 15건 / 최종 24건, 루브릭·안전 기준 통과 | OpenAI 가상 입력, 실제 실행은 API 연결 이후 | 실제 입력은 클라우드 비교에 사용하지 않음 |
| 표현 품질 | 필수 섹션 누락·단정적 예언·극의 우열 표현 0건 | 최종 24건 전수 사람 검수 | 자동 검사만으로 품질 통과 선언 금지 |
| 조작 접근성 | 키보드 주요 흐름 완료, 대비·줄바꿈 기준 통과 | 구현 후 지정 화면 폭 및 VoiceOver 검사 | 현재 준수 인증 없음 |

## 8. 설계 기본안과 남은 검증

- 공유 결과의 7일 보관, 저장 티켓 10분은 구현 범위를 작게 유지하기 위한 제안값이다. 법률·기존 정책에서 나온 기간이 아니다.
- 원본보다 더 적은 정보를 공유한다. 공유 결과에는 사주 기둥·생년월일·성별·개별 MBTI가 없다.
- 보관 기간과 삭제 정책 변경은 기존 결과의 수명을 몰래 연장하지 않는다.
- 실제 이용자 조사와 UI 테스트는 아직 없다. 시연 전 최소한 입력·공유·삭제에 대한 사용성 점검이 필요하다.
- 상세한 기술 의존성과 검증 선행 조건은 테크스펙의 준비도 표를 따른다.
