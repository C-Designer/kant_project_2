> **2026-10-11 최신 범위:** 사용자가 배포 사이트의 실제 사용자 요청을 서버 OpenAI 키로 처리하도록 확정했다. 동의한 요청의 파생 사주 정보·MBTI만 전송하며 원문 생년월일시와 성별은 서버에 남긴다. 입력의 DB·로그·학습 저장은 금지한다. 키·모델·두 활성화 플래그가 없으면 비활성이다. 현행 실행 계약은 [API 연결 인계](./API_HANDOFF.md)와 TECH_SPEC §12이며, 이전의 “가상 CLI만/실제 입력 영구 차단” 규칙을 대체한다. ## 1. 디자인 방향 — 사이의 발견

러브코드는 두 사람의 관계 스타일을 읽고 이야기하게 하는 **관계 매거진**이다. 사람을 평가하는 결과표나 운명을 판정하는 권위를 브랜드로 삼지 않는다.

- **확정 근거:** 사용자가 관계 매거진, 담백하고 영리한 문장, 타이포와 추상 그래픽을 선택했다. 기존 화면이 투박하다는 피드백을 받았다.
- **디자인 제안:** 종이색·짙은 녹색 잉크·시트러스, 대형 한글 제목, 얇은 편집 구분선, 두 선의 겹침을 시그니처로 채택한다.
- **남길 인상:** 감각적, 명료함, 친밀함. 피할 인상: 유아적.
- **기억할 장치:** 같은 굵기의 두 선이 만나 새 공간을 만드는 모양. 장식은 이 장치와 제목의 굵기 대비에 집중한다.
- **강도:** 시각적 변주 4/5, 움직임 1/5, 정보 밀도 2/5. 큰 제목은 홈·결과 첫머리에 집중하고 폼에는 절제한다.
- **카피:** “닮은 점. 다른 점. 그 사이의 우리.” 기능 설명은 “사주와 MBTI로 읽는 두 사람의 관계 스타일.”
- **가정:** 처음 방문한 사용자가 관계유형을 편하게 살펴보려 한다. 대표 사용자 조사나 사용성 검증을 수행한 것은 아니다.

시각 보드: [brand-board.html](./design/brand-board.html). 이는 실제 분석 기능이 없는 브랜드 기준 견본이다. v0.2의 커플 캐릭터·로즈색·둥근 카드 중심 방향을 대체한다. 과거 시안과 캐릭터는 현행 브랜드 자산으로 재사용하지 않는다.

### 형태와 그래픽 규칙

- 워드마크는 ‘러브코드’ 한글을 중심으로 한다. 보드의 워드마크는 조판 시안이며 완성된 로고 원본이 아니다.
- 두 인물을 얼굴·성별로 그리지 않는다. 같은 굵기와 시각적 비중의 두 선을 사용한다.
- 겹침·간격·리듬을 변주하되 실측값·확률·관계 강도를 나타내는 차트로 오해시키지 않는다.
- 16유형은 네 개의 정확한 한글 라벨로 구분한다. 유형별 그래픽 규칙은 아직 확정하지 않았으며 장식 변주를 결과의 근거처럼 연결하지 않는다.
- 상징은 SVG로 구성한다. 정보를 라벨과 중복 전달하면 aria-hidden으로 처리한다. 데이터 차트·진행률·유형 점수는 추가하지 않는다.
- 카드보다 구분선, 그림자보다 명암, 장식보다 글자 위계를 우선한다. 하트·이모지·유리 효과·반복 그라데이션을 브랜드 장치로 쓰지 않는다.

## 2. 정보 구조와 경로

| 경로 | 목적 | 주 행동 | 들어오는 경로 |
| --- | --- | --- | --- |
| `/` | 서비스 이해·시작 | 궁합 알아보기 | 직접 방문·검색용 일반 소개 |
| `/test` | 두 사람 입력·분석·미저장 결과 확인 | 결과 보기 → 공유 링크 만들기 | 소개 CTA |
| `/r#<read_token>` | 저장 결과 읽기 | 나도 궁합 알아보기 | 사용자가 복사한 링크 |
| `/manage` | 삭제키로 공유 결과 폐기 | 결과 삭제 | 저장 완료 패널의 결과 관리 또는 직접 방문 |

별도 마이페이지·유형 도감·전체 결과 목록은 없다. 첫 번째 사람/두 번째 사람 표시는 입력 순서일 뿐 나이·성별·관계 역할을 뜻하지 않는다.

### 소개 화면

```text
러브코드

닮은 점. 다른 점.
그 사이의 우리.
사주와 MBTI로 읽는 두 사람의 관계 스타일.
[두 선이 겹치는 추상 그래픽]
[우리 사이 알아보기]

닮은 점 · 애정 표현 · 함께하는 거리 · 대화의 속도
참고·오락용 해석 안내
```

헤드라인·설명·한 개 CTA가 먼저 보이게 한다. 후기·사용자 수·정확도·성공 사례를 만들지 않는다. 설명에 분류 모델명·FastAPI·토큰 같은 구현 용어를 노출하지 않는다.

### 입력 화면

```text
두 사람을 알려주세요
양력 · 한국 표준시 기준이에요.

첫 번째 사람              두 번째 사람
성별                     성별
생년월일                 생년월일
태어난 시간 [모름]         태어난 시간 [모름]
MBTI                     MBTI

□ 두 사람의 정보를 이 분석에 사용해도 되는지 확인했어요.
입력한 정보는 분석에만 사용하고 저장하지 않아요.
[우리 관계 알아보기]
```

모바일에서는 첫 번째 사람 전체 → 두 번째 사람 전체 → 확인·CTA 순서다. 데스크톱에서만 두 인물 폼을 나란히 배치한다(2026-10-15 구현: 단계 이동 없이 한 화면, 동의 체크 하나, 성별은 세 버튼, MBTI는 네 축 두 버튼씩). 성별·MBTI는 기본 선택하지 않는다. 생시 모름을 선택하면 시각을 null로 바꾸고 기존 시각을 요청에 보내지 않는다. 다시 해제하면 시각을 새로 입력하게 하여 숨은 이전 값으로 분석하지 않는다.

### 결과 화면

```text
우리의 관계 스타일
[짧은 추상 그래픽, 제목보다 낮은 위계]
연애 케미    보완형
연애 온도    열정형
관계 거리    독립형
갈등 해결    시간 두기

한 줄 요약
잘 맞는 점          2개
맞춰 갈 점          2개
이렇게 이야기해 봐요 1개

[생시 모름 제한 안내, 해당할 때만]
[공유 링크 만들기]   [다시 해보기]
참고·오락용 해석 안내
```

위 라벨 조합은 레이아웃 예시이며 특정 생일의 검증 결과가 아니다. 해설 예시를 검증된 사실이나 모델 출력으로 표시하지 않는다. 내부 ID·유형 확률·궁합 퍼센트·진행률 막대를 보여주지 않는다.

### 공유 완료와 결과 관리

저장 확인 dialog 내용:

> 결과와 해설만 7일 동안 저장해요. 생년월일시·성별·MBTI는 저장하거나 공유하지 않아요. 링크를 가진 사람은 결과를 볼 수 있어요.

버튼은 `취소` / `저장하고 링크 만들기`. 완료 패널에는 읽기 링크·만료일·별도 삭제키를 서로 다른 영역에 둔다. `공유 링크 복사`와 `삭제키 복사`를 구분한다. 삭제키 영역의 안내는 “삭제키는 혼자 보관해 주세요. 잃어버리면 만료일까지 직접 삭제할 수 없어요.”다.

`/manage`에서는 삭제용 정보 `<result_id>.<delete_token>` 하나를 붙여넣는다. 사용자 라벨은 `삭제키`, 기술 형식은 표시하지 않는다. UI에는 원래 결과 내용을 불러오지 않으며 삭제키만으로 결과를 읽을 수 없다. 삭제 확인은 “이 결과를 삭제할까요? 공유 링크도 사용할 수 없게 되고 복원할 수 없어요.”, 버튼은 `취소` / `결과 삭제`다.

## 4. 글자·간격·형태

### 타이포그래피

한글 제목이 주인공이다. 한 제목에서 중간 굵기와 굵은 글자를 최대 두 단계로 써 호흡을 만든다. 영문 세리프는 짧은 편집 문구 한 곳에만 쓴다. 폼 라벨·오류·개인정보 안내를 영문이나 모노스페이스로 꾸미지 않는다.

| 타입 토큰 | desktop / mobile | weight·line-height | 용도 |
| --- | --- | --- | --- |
| `type.display` | 88 / 44px, 유동 42~94 | 700~800 · 1.15 | 홈 대표 제목 |
| `type.display-light` | display와 동일 | 350~400 · 1.15 | 제목 안 한 구절 |
| `type.h1` | 48 / 32px | 650~700 · 1.25 | 입력·결과 제목 |
| `type.h2` | 32 / 26px | 650 · 1.35 | 큰 섹션 |
| `type.h3` | 22 / 20px | 600 · 1.4 | 인물·해설 제목 |
| `type.body` | 16 / 16px | 400 · 1.7 | 본문·필수 안내 |
| `type.label` | 14 / 14px | 600 · 1.5 | 폼·축 제목 |
| `type.caption` | 12 / 12px | 400 · 1.5 | 비필수 보조 메타데이터 |

보드는 설치된 한국어 시스템 산세리프와 Georgia로 표현한다. **최종 브랜드 전용 서체는 미선정**이다. 새 서체 파일·외부 폰트 요청은 추가하지 않았다. 본앱 적용 시 사용권·한글 렌더·자체 호스팅·가중치 지원을 확인해 확정한다. 시스템 폰트 이름 자체를 브랜드 차별성으로 주장하지 않는다.

제목 자간은 -0.04~-0.07em, 본문은 0~-0.015em을 출발점으로 하고 실제 한글 겹침을 확인한다. CSS는 rem과 clamp를 사용한다. 제목 줄바꿈은 의미 단위로, 긴 해설에는 강제 줄바꿈을 넣지 않는다. 본문 폭은 최대 36rem, 결과 전체는 48rem. 영문은 의미 없는 대문자 장식으로 반복하지 않는다.

### 공간·표면

- spacing: 4, 8, 12, 16, 24, 32, 48, 64, 96px.
- 전체 지면: 최대 1280px. 홈은 12열을 기준으로 제목7/그래픽5 정도의 비대칭 구도를 사용한다.
- page padding: 모바일 20~24px, 중간 화면 36px, 큰 화면 64px.
- 섹션 사이 64~96px, 필드 사이24px, 라벨→입력8px. 여백을 늘리려고 긴 필수 안내를 줄이지 않는다.
- radius: 버튼2px, 입력4px, dialog8px. 일반 섹션은 라운드 카드로 감싸지 않는다. 유형 라벨의 pill을 제거한다.
- border: 일반 편집 구분선1px, 조작 경계1px, focus3px/offset3px. 얇은 장식선은 입력 경계 대신 쓰지 않는다.
- shadow: dialog에만 최소 그림자. 일반 지면·축 요약·버튼에는 그림자 없음.
- 입력·버튼 높이 최소48px, 아이콘 hit area44px. 버튼은 잉크색 solid / 밑줄 또는 outline secondary. CTA 화살표는 보조 장식이다.
- 기본 레이아웃은 편집 행과 여백이다. ResultSection은 얇은 구분선 아래 제목·본문, AxisSummary는 네 행 description list로 구성한다.

## 5. 반응형 규칙

| 폭 | 구조 |
| --- | --- |
| 320~767px | 대표 제목→짧은 설명→CTA→축소 그래픽 순서. 폼1열, 축4행, 주요 행동 전체 폭 가능 |
| 768~1023px | 홈2열은 제목 줄바꿈을 확인한 경우에만. 폼2열, 본문은 읽기 폭 유지 |
| 1024px 이상 | 비대칭 홈 지면·폼2열. 결과는48rem 안에서 요약과4축을 편집 |

모바일 첫 화면에서 그림이 CTA를 밀어내지 않도록 한다. 장식 때문에 가로 스크롤을 만들지 않는다. 축·성별·입력 순서는 DOM 의미를 유지한다. dialog 좌우16px 여백, 최대높이 calc(100dvh - 32px), 내부 스크롤을 사용한다. 하단 고정 CTA는 제외한다.

앱 적용 검증 폭은320/390/768/1280 CSS px. 브라우저 배율과 viewport 설정값 차이가 있으면 실제 innerWidth로 기록한다. 200%확대·긴 오류·최대 해설·URL·삭제키·가상 키보드도 검증한다. 브랜드 보드 검토를 실제 폼·공유 여정 검증으로 대체하지 않는다.

## 8. 로딩·모션·접근성

- 분석 API가 실제 단계 이벤트를 제공하지 않으므로 “계산 30% → 해석 70%” 같은 가짜 단계·퍼센트를 표시하지 않는다.
- 짧은 저장·복사는 버튼 옆 상태 문구만 사용한다. 전체 화면 skeleton으로 현재 결과를 지우지 않는다.
- 빠른 응답을 늦춰 애니메이션을 끝내지 않는다. 여러 영역이 한 응답으로 오는 분석 결과에 부분 진행을 가장하지 않는다.
- motion token: 피드백 120ms, 패널 fade 160ms, dialog 180ms. easing `cubic-bezier(0.25, 1, 0.5, 1)`, opacity·transform만 우선 사용한다.
- reduced motion에서는 움직임을 제거하고 정적 상태를 즉시 보여준다. 자동 폭죽·무한 떠다니기·heartbeat 효과 없음.
- focus: `3px solid color.focus`, offset 3px. 배경이 바뀌어도 outline이 사라지지 않는다.
- 모든 동작을 Tab·Shift+Tab·Enter·Space·Escape로 수행한다. native select 키 동작을 유지한다.
- 상태 메시지는 `role=status`/polite 한 곳으로 알린다. 오류는 중복 낭독하지 않으며 spinner·skeleton은 읽기 내용이 아니다.
- 삭제·공유 dialog에는 제목과 설명을 연결하고 배경 초점을 막는다. 닫으면 호출 버튼으로 돌아간다.
- 한글 IME 조합 중 Enter를 submit으로 처리하지 않는다. focus 이동·자동 trim·case 변환은 composition 종료 후 한다.
- 그림이 정보성이라면 장면을 설명하는 짧은 alt를 쓰고, 이미 네 라벨이 같은 뜻을 전달하면 중복 장식 그림은 빈 alt로 둔다. 텍스트를 그림 안에 굽지 않는다.
- 스크린리더·키보드·색 대비·확대·forced-colors는 구현 후 검증한다. 지금 단계에서 WCAG 준수 인증을 주장하지 않는다.

날짜 표시는 Intl 형식으로 한국어·Asia/Seoul을 명시한다. `{expiresAt}` 예시 “2026년 10월 18일 오후 3:20 (한국 시간)”처럼 사용자에게 이해되는 값으로 변환한다. 날짜를 만료일만 표시해 정확한 시각을 숨기지 않는다.

“천생연분 보장”, “바람필 확률”, “헤어질 운명”, “위험한 사람”, “정확도 99%” 등 입증되지 않은·단정적인 문구를 금지한다. “보완형은 더 좋은 궁합”처럼 한 극에 순위를 부여하지 않는다. 실제 모델명을 결과 가치의 근거처럼 광고하지 않는다.

## 16가지 관계유형 안내 페이지

`/types`는 API나 사용자 입력 없이 읽을 수 있는 관계유형 사전이다. 4×4 그림 목록 → `/types/[slug]` 개별 상세 → 분석 진입으로 구성한다. 모바일에서도 4열을 유지하며 읽기 쉬운 HTML 이름을 별도 표시한다. 상세에는 같은 그림, 네 축, 강점, 조율할 점, 대화 예시, 이전·다음 유형을 제공한다.

2026-10-11 사용자 제공 1024×1536 포스터를 원본 그대로 `frontend/public/images/types/user-relationship-sheet.png`에 보관했다. CSS 배경 좌표로 16개 영역을 표시하며 새로 생성하거나 원본을 수정하지 않는다. 이름·한 줄 문구·배치 순서는 원본을 따른다. 원본의 별명은 표현용 이름으로 기존 4축 조합에 편집상 연결한 것이며, 원본 자체가 canonical 분류를 정의한 것은 아니다. backend taxonomy와 학습 라벨은 변경하지 않았다. 연결 관계와 영역 좌표는 `frontend/data/relationship-types.json`이 관리한다. 개인 분석·검증된 심리 진단으로 표현하지 않는다.

- 강도: 시각적 변화 3/5, 모션 1/5, 정보 밀도 3/5. 진입 애니메이션이나 추가 폰트·라이브러리는 도입하지 않았다.
- 색: canvas #FFFAF2, surface #FFFDF8, text #342E29, muted #71665C, brand #885039, soft #F3EBDF, border #D9CBBB, focus #386755. 동작 색은 갈색, 일러스트의 다양한 색은 원본 그대로 유지한다.
- 형태: 버튼 12px, 입력 8px, 결과 요약 16px. 설명은 선과 여백으로 구분하며 모든 문단을 카드로 감싸지 않는다.
- 홈: 구체적 질문 → 궁합 시작/예시 바로보기 → 유형 그림 → 네 가지 기준. 유형 목록은 기존 요청대로 모바일에서도 4×4를 유지한다.
- 입력: 첫 번째 사람 → 두 번째 사람 → 확인/동의. 필수값 검증은 현재 단계에 적용하며 이전 입력 필드는 DOM에 유지해 값을 보존한다. 단계 변경 시 제목으로 포커스를 옮긴다. 새로고침·페이지 이탈 시 입력은 보존하지 않고 브라우저 저장소에도 저장하지 않는다.
- 결과: 유형 이름을 h1로, 개별 요약을 h2로 표시한다. 상세는 결과·공유 상태를 유지하기 위해 새 탭으로 연다. 예시에서 입력으로 돌아오면 입력값을 유지한다.
- 공유/삭제: 기존 동의·7일 만료·삭제키·확인 dialog 정책 유지. 공통 색·타이포·여백과 둥근 컨트롤을 적용한다.
- 실제 분석 불가 상태는 사전에 표시하고 최종 분석 버튼을 비활성화한다. 예시 결과는 홈에서 직접 열 수 있다. AI 초안·미검수·모의 API 상태 표시를 숨기지 않는다.
