# 러브코드 MVP 문서

> 2026-10-13 정리: 저장·공유·삭제 백엔드, PostgreSQL 및 서명 티켓을 완전히 제거했습니다. 아래의 해당 기능 설명은 과거 설계 이력이며 현재 구현 범위가 아닙니다. 현재 실행과 코드 탐색은 [README](../README.md)와 [CODE_GUIDE](./CODE_GUIDE.md), HTTP 스키마는 [OpenAPI](./api/openapi.json)를 따릅니다.

작성일: 2026-10-11 · 버전: 0.3 · 상태: 실제 API 요청 경로 구현·모의 통합 검증

러브코드는 두 사람의 사주·MBTI를 바탕으로 관계 스타일을 16유형 중 하나로 보여주는 참고·오락용 웹서비스다. 이 문서 묶음은 **과제·발표용 MVP / 관계 매거진 브랜드 / Next.js / 서버 저장·공유 링크**라는 사용자 결정을 따른다.

| 문서 | 결정하는 내용 |

| [데이터 스키마](./DATA_SCHEMA.md) | 입력·출력 필드, 학습 CSV, 16유형 사전, 저장 테이블과 제약 |
| [디자인 시스템](./DESIGN_SYSTEM.md) | 화면 구조, 컬러·타입·간격, 컴포넌트, 상태, 카피, 접근성 |

제품 범위는 PRD, 필드·enum은 데이터 스키마, 처리·수명주기는 테크스펙, 표현·상호작용은 디자인 시스템이 기준이다. 내용이 충돌하면 구현으로 임의 해결하지 않고 해당 문서들을 함께 수정한다. 기존 문서의 이동·삭제는 없다.

학습 자료: [러브코드로 배우는 FastAPI와 LangChain](./learn/fastapi-langchain.html)은 현재 백엔드 코드를 교재로, 요청 한 건이 지나는 10단계(공유 링크 포함)를 한눈에·파일 따라가기·원리 파고들기 세 깊이로 설명하는 단일 HTML 페이지다. 히스토리 탭, 요청 시뮬레이터, 퀴즈 6세트가 함께 있다. 설계 기준 문서가 아니라 학습용이며, 브라우저로 직접 열거나 배포 사이트의 `/learn`에서 본다. 원고와 조립 방법은 [learn/src/README](./learn/src/README.md)를 따른다.

## 근거와 상태

- **확인된 초기 결정:** 대화에서 사용자가 `1A / 2A / 3B / 4C`를 선택했다.
- **브랜드 개정:** 이후 사용자 `1A / 2A / 3A`로 관계 매거진·담백한 문장·타이포/추상 그래픽 방향을 선택했다. [브랜드 보드](./design/brand-board.html)와 디자인 시스템 v0.3이 현행 기준이다. 홈·입력·결과·공유·관리 화면에 적용했다. 변경 후 확인은 [앱 검토 기록](../artifacts/qa/BRAND_APP_REVIEW.md)에 있다.
- **확인된 원문:** 러브코드 프로젝트 제안서 (내부 자료), 2026-10-11 Aside로 읽음. 사주 계산 → 텍스트 변환 → 단일 16유형 분류 → 한글 유형 표시 → 해설 생성 구조다.
- **확인된 작업공간:** 작성 시작 시 프로젝트 폴더는 비어 있었고 코드·패키지·AGENTS.md·기존 문서는 없었다. 기존 시스템을 설명하는 문서가 아니라 신규 설계다.
- **이번 설계 기본안:** 공유를 선택한 결과만 저장, 저장 후 7일 만료, 읽기 권한과 삭제 권한 분리, 원본 입력 미저장, PostgreSQL 사용. 사용자가 개별 승인한 사실이나 법정 보관 기간으로 표현하지 않는다.
- **현재 작업 범위:** CSV 생성·앱·로컬 DB·OpenAI 연결 코드와 호출 없는 검증을 완료한다. 실제 API·학습·해설 평가는 내일 이후 단계다. [검증 기록](./VALIDATION.md), [API 인계](./API_HANDOFF.md)를 따른다.

## 구현을 시작할 때 확인할 사항

추가 제품 질문 대신 아래 기본안으로 설계했다. 구현자는 구현 시작 시 기본안을 확인하고 차이가 있으면 문서 버전을 올린다.

| 항목 | 기본안 / 완료 조건 | 결정 시점 |
| --- | --- | --- |
| 공유 보관 | 7일, 삭제 후 복원 없음, 원본 입력 저장 없음 | 결과 저장 기능 구현 전 |
| 만세력 엔진 | 계산 규약에 맞는 엔진·버전 고정, 약 20개 기준 사례 검증 | 실제 사주 계산 연결 전 |
| 분류 모델 | TF-IDF+LR / 한국어 사전학습 인코더 비교 후 선정 | 최종 서비스 모델 연결 전 |
| 해설 모델 | 로컬 생성 제외, OpenAI 서버 호출로 동의한 실제 요청 처리·가상 데이터 실험 | AI 연결 전 |
| 책임자 | 프로젝트 팀이 개발·데이터 검수·시연 운영 담당자를 지정 | 검증 계획 실행 전 |

앞서 만든 16유형 이미지와 별명은 **이전 축 구성의 탐색 시안**이다. 현행 분류 라벨이나 확정된 디자인 자산으로 사용하지 않는다. 노션의 도윤·서아 사주 예시도 경도 보정 제거 전 초안이므로 검증 정답으로 재사용하지 않는다.

## 문서 검증 기록

- 작업 디렉터리: 저장소 루트.
- 조사 명령: `pwd && rg --files -g 'AGENTS.md' -g '*.md' -g 'package.json' -g 'pyproject.toml' -g '!node_modules' -g '!.git' | head -80`, 종료 코드 0. 파일 목록 출력 없음.
- `ls -la` 및 상위 경로 AGENTS.md 확인 명령 종료 코드 0. 빈 작업 폴더, 적용할 추가 지침 없음.
- 작성 후 검증 범위: 로컬 문서 링크, 16개 유형 조합의 중복·누락, 필수 CSV 헤더, 문서 간 정책 일치, 토큰 색상 대비의 수치 계산.
- 초기 문서 작성 시에는 실행 UI가 없었다. 현재의 브라우저·자동 검증 증거는 VALIDATION.md에 추가했다. 스크린리더·모델 성능·만세력 전 범위 정확도·부하 측정은 미실행이다.
- 2026-10-11 Python 표준 라이브러리로 문서 정적 검사를 실행했다(종료 코드 0): 16개 유형의 전체 조합·ID·label 일치, CSV 7컬럼 헤더, 17개 요구사항의 AC/TEST 연결, 로컬 파일 링크·코드 펜스 검사가 통과했다.
- 주요 색상 조합 10개를 수식으로 검사했다. 본문/배경 13.72:1, 보조 글자/배경 5.29:1, 주요 버튼 흰 글자 6.12:1, 입력 경계/흰 배경 3.95:1이다. 나머지 검사 조합도 설정한 텍스트·조작 대비 하한을 통과했다.
- 내용 대조에서 생시 모름의 절기 경계 처리를 수정했다. 오류나 임의 시각 대신 후보 기둥·확정 근거·불확실성 안내를 사용하여 원문의 생시 모름 허용 원칙을 유지했다.
